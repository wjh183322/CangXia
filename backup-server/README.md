# 藏匣 NAS 备份服务 0.2.4

配套桌面版 **0.3.36**，协议 **3**，数据库 schema **4**。明确删除的范围只有经过用户恢复确认才允许重新写入，替换旧版删除后自动补传规则。

## 更新现有服务

1. 暂停各电脑任务、完成需要保留的同步并退出；停止旧容器，备份**整个原 data 目录**，包括数据库、objects、密钥和证书。
2. 导入 CangXia-Backup-Server-0.2.4.tar，原项目镜像改为 cangxia-backup-server:0.2.4 后重新部署。保留数据挂载、端口绑定、环境与网络配置，不覆盖已有 .env。
3. 首次启动建立 library.pre-schema-4-*.sqlite 一致性副本，校验后事务迁移。保留原库 ID、媒体、密钥和证书，失败不开始新协议写入。
4. 所有电脑安装桌面 0.3.36，用原地址、访问密钥和 SHA256 证书指纹重新检查连接。**不清缓存、不清资料、不重读收藏。**

旧桌面可继续浏览本机，但不能向新服务写入；新桌面连接旧服务也不执行新删除功能。命令行导入示例：docker load -i CangXia-Backup-Server-0.2.4.tar。实际挂载路径以原配置为准。

## 新部署

使用 compose.yaml 和 .env.example，设置局域网绑定地址。首次启动生成访问密钥和 TLS 证书，Windows 加密保存连接密钥。默认 TCP 18443；Tailscale 原规则只有 SMB 445 时额外允许指定电脑到 NAS 的 18443，保留旧规则，不需要公网端口映射。

## 删除和恢复

- 读取记录按账号收藏或具体作者分别处理。账号范围含该作品全部自建收藏夹关联，其他作者来源保留。
- 文件含正式视频、图片、高清图和永久配乐引用。多个来源共用该份文件，其他作品仍引用的共享音频保留。
- 可以仅本机移除或同时删除 NAS；原有 NAS-only 入口保留本机副本，但不会自动传回。
- 本机移除后同步不自动补回，可在独立 NAS 目录查回记录、分别恢复来源或文件；仅记录不会被显示为有原视频。
- 另一电脑保留对应内容，集中显示删除电脑、时间和范围，选择保留并上传、删除本机对应内容或稍后处理。未选择范围阻止回传，其他资料可继续。
- NAS 先返回同一操作回执，再执行已确认本机步骤。路径变化、共用目录或回收站失败保留该项，重启不自动删除。

媒体按 SHA256 保存，相同内容不重复上传。普通记录、封面和配乐通路不能绕过版本；恢复授权随分块请求续期并核对最新范围。

## 目录和保留

目录同时包含仅记录与媒体副本，来源/关键词索引先筛选后分页。浏览无需写入租约，图像和视频按需读取，配乐/封面沿用受限缓存。

已完成操作正文保留 90 天、总预算 50 MiB；最小幂等凭据、最新版本、未解决待处理和持有信息不清除。旧操作重试不再次删除。超过 24 小时的未提交片段仅在没有引用、活动上传/读取或有效恢复保护时回收，删除前复核。

## 数据与回退

data/library.sqlite 保存记录、版本、回执和目录；data/objects 保存正式内容；data/uploads 保存暂存。data/access-token、证书和私钥是连接身份，升级保留整个 data。

迁移前数据库副本不能替代完整卷备份。回退须停止新服务，恢复升级前**整个一致性 data 副本**并使用匹配旧服务/旧桌面；不能让旧服务打开 schema 4，不能只换回数据库而保留已删除对象的现状。使用新版本恢复较早快照时也需核对桌面缓存和待确认操作，不能直接重放旧删除请求。

镜像不含用户数据、密钥或证书。发布不自动部署容器、不执行用户删除；隔离测试与遵义/重庆实机验收分别记录。

# 藏匣备份服务 0.1.0

本服务供“藏匣备份版”使用。与现有“藏匣 NAS 版”的 `.cangxia` 目录和 SMB 直写协议分开。

## 在绿联 NAS 部署

1. 新建专用文件夹，例如 `CangXiaBackupService`。把本包的 `compose.yaml` 放入这个文件夹。
2. 将 `.env.example` 复制为 `.env`，填写 NAS 自己的 Tailscale IPv4 地址。
3. 从同一版本 Release 下载 `CangXia-Backup-Server-0.1.0.tar.gz`。如导入窗口不识别压缩文件，先解压得到 `.tar`。
4. Docker → 镜像 → 新建镜像 → 从 NAS，导入镜像文件。成功后应有 `cangxia-backup-server:0.1.0`。
5. Docker → 项目 → 创建，选择上面的专用文件夹，导入 `compose.yaml` 并部署。
6. 在容器日志中复制 `Access token` 和 `Certificate SHA256`，直接填入电脑端的备份服务设置。
7. 电脑端地址填写 `https://NAS的Tailscale地址:18443`。访问密钥在电脑上由 Windows 加密保存，证书按指纹核对。

如果 Tailscale 访问规则目前只允许 SMB 的 TCP 445，需要在原规则中额外允许指定电脑访问这台 NAS 的 TCP 18443。保留原有规则，不需要路由器公网端口映射。

## 保存位置

- `./data/library.sqlite`：服务端记录、设备及提交历史。
- `./data/objects/`：按内容摘要保存的媒体，新增上传后在 NAS 本机计算 SHA256。
- `./data/uploads/`：可续传的上传暂存文件。
- `./data/access-token`、TLS 证书及私钥：首次运行时生成。后续重新部署保留整个 `data` 目录。

证书指纹用于确认连接的就是这台服务；密钥用于访问授权。镜像包中不包含任何用户密钥、证书或资料。

## 行为

电脑先核对同步状态，再取得单机写入权。其他电脑可更新已提交的记录并只读浏览。断线后暂停修改，保留本机尚未同步的内容。租约在正常退出时释放，异常退出后约 90 秒到期。

新媒体分块上传，已存在的相同内容跳过；更新收藏和标签只提交变化记录。数据提交有基础状态检查，双方都有更新时不会直接覆盖。

本机文件清理不自动删除 NAS 已有的备份。服务尚不自动清理历史对象和残留上传，后续需增加容量管理。这里的同步副本仍位于同一台 NAS，独立硬盘备份继续保留为后续事项。

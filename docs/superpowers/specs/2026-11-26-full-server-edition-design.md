# 藏匣服务版完整版设计

2026-11-26 · 方案已选定，设计待用户审阅

## 交付目标和方案选择

交付一套可安装的 Windows 客户端和一个可拉取的 NAS 应用镜像。用户在熟悉的藏匣界面里读收藏、查作者、看作品、整理目录、补齐下载；关掉这台电脑后，已入队的下载继续。换电脑打开藏匣，看到同一个库、同一套文件和 NAS 已确认的进度。开发中可独立验证各模块，交付范围按完整版一次验收。

| 本轮讨论的客户端方案 | 收益与成本 | 决定 |
| --- | --- | --- |
| A．沿用备份版客户端，逐项接入 NAS | 保留页面、快捷操作和任务反馈；需要逐项找出主进程中对本机文件、数据库和路径的依赖 | 用户选定 |
| B．新建客户端并复用页面组件 | 客户端分层可以从零划定；播放器、批选和跨页状态等已有行为需要重新接线和验收 | 作为比较方案 |

本轮字母用于区分客户端实现。采集位置沿用此前确认的 NAS 采集架构（11 月 19 日文档中的“方案 B”）。Windows 管交互，NAS 管来源浏览器、正式资料库、任务和归档媒体。

正式代码、产品测试及后续正式构建工作流在 GitHub 分支 `codex/server-edition-full` 开发，起点为试验分支 `codex/server-edition` 的 `e2ac5b1`。试验镜像继续使用原工作流和包名。正式候选采用独立的构建和发布配置，正式包对外发布时另核对可见性和授权。试验工作目录里未提交的解析器改动作为待对照项，实施时先核查详情字段与共同作者回归，再决定是否移植。

业务对照版本固定为藏匣备份版 0.3.46，提交 `08e6436522a3828211e9c32b51f90d7d830b4fa8`。功能对照由该提交的 `src/` 页面、`electron/preload.cjs` 的方法和事件、主进程处理器以及对应测试共同定义；基线表遗漏的可用入口同样要对照。NAS 原型已有独立的[现场验证记录](../../server-edition/README.md)。正式客户端、正式库及镜像使用独立身份，交付前核对分支、产品名、安装位置、用户数据目录及卷标识，允许和旧版并存。

## 从用户操作到正式结果

| 备份版入口或行为 | 服务版的实现与验收 |
| --- | --- |
| 资料库、收藏夹、作者、搜索筛选、排序分页、标签、批选 | Windows 保留布局、快捷操作、当前位置与返回行为。由 NAS 按原规则查询和修改；筛选后的跨页批选在同一选择范围内执行，确认时说明范围和数量。已保存、未明确移除的作品即使没有媒体或收藏归属也可找到。 |
| 总收藏、自建夹、作者、分享链接、快速/完整读取、历史 | 从原入口启动 NAS 作业。保留确认、续读、结束及读取历史语义；作品、关系、顺序、游标用精确字符串身份关联。总收藏正式保存且必要整理完成后才跟进收藏夹；普通单夹错误按原规则记录并继续，账号、限流和存储故障暂停相应批次。 |
| 作品详情、创作者、图集、视频和配乐 | 列表与详情分别补充；保留共同作者及核验状态、图集顺序和尺寸、视频候选、音频提示与手工标签。未知字段保留旧可靠值。预览和播放使用当前会话授权，支持范围请求、拖动、切换和取消；缓存按库、资源身份及版本区分。 |
| 下载、队列、预览选择、暂停、取消、重试、补齐、缺陷检查与修复 | NAS 在确认入队前持久保存必要资源清单；重复命令查询原作业。可验证同一资源时续传，否则从头传该资源，保留已完成项。取消先停写入，再清理该任务的暂存。界面分开显示传输中断、来源不可用、登记失败及清理失败。 |
| 普通单图、高清封面、图文、视频归档 | 沿用现有资源选择、质量比较与命名规则。高清匹配复用现有 OpenCV/NumPy 算法、可信阈值及拒绝样本。NAS 保存普通文件及对应大小和 SHA256；一件作品可属多个来源，归档位置独立于归属表。自动移夹、改名、重名防覆盖和必要的作品信息 JSON 更新按备份版执行，失败保留可恢复记录。 |
| 单独下载/平铺导出、打开原作品 | 普通下载由 NAS 归档。移除旧版本地下载根目录和作品归档文件夹的打开入口，Windows 无需通过 SMB 定位 NAS 归档。保留其他有实际本地目标的目录操作，包括选择和打开单独导出目录、在设置中打开临时缓存目录。平铺导出沿用排序、图集及可选封面范围，仅在本次运行中执行，独立于 NAS 归档完成标记。 |
| 存储统计、检查、删除、回收、恢复与诊断 | 分开核对作品记录、来源归属、正式文件、待处理任务和本机缓存。预览后按确认范围执行；恢复需要检查删除版本和目标冲突。正式媒体优先使用经实际删除和还原验证的 NAS 回收站，记录原路径、身份及操作回执；恢复目标被占用时保留两者供处理。外部改名、文件缺失或平台返回 403 均不能触发删除其他记录。诊断可区分发生阶段并脱敏。 |

### 旧版同步入口的拟议映射（本设计请用户审阅）

保留原入口附近的连接、状态和处理操作，让使用者能判断“存在哪里、能否换电脑、此次会动什么”。设计采用以下语义；实施计划列出原按钮、状态、确认文案及对应测试，方便逐项核对。

| 原入口/提示 | 服务版中的可见结果 |
| --- | --- |
| 备份连接、检查同步状态 | 设置 NAS 地址、服务访问凭据、证书指纹和设备名；显示所连资料库、当前使用权和最近操作结果。 |
| 待同步、立即同步／换电脑前同步、退出等待 | 已被 NAS 确认的操作可在另一台电脑查询；回执待确认时显示“正在核对”。换机入口先查回执，再释放使用权；已入队下载仍可继续。 |
| 双方更新、采用 NAS、旧库恢复 | 日常重新连接直接读取 NAS。旧库和历史副本进入下述迁移预览；用户可查看差异、保护范围和候选，明确选择后写入独立目标。 |
| 本地已存、NAS 已备份、恢复到本地 | 作品的“已下载”取自 NAS 归档记录和文件校验结果。缓存占用与清理放在 Windows 客户端设置；需要带走文件时使用导出。备份时间和覆盖范围单列。 |

### Windows 上会留下什么

正式版新下载的视频、图片、配乐及其作品信息统一归档到 NAS。Windows 保存应用、连接设置和可清理的浏览/播放缓存。平铺导出由用户明确发起，导出文件归用户管理。旧备份版已经下载到电脑的媒体属于迁移输入，迁移前后均保留到用户自行决定处置。针对原“仅本机移除”，本稿建议取消作品级入口及按电脑隐藏作品的规则；在设置里清理缓存即可。删除 NAS 媒体、删除作品记录、移除收藏夹归属各自列明影响范围，所有电脑下次查询都看到 NAS 确认的结果。

### 打开抖音原作品

0.3.46 的作品详情、读取历史和缺陷检查入口向主进程传入数字作品 ID。主进程优先使用作品记录中的 URL，无 URL 时用 ID 构造抖音作品链接；校验 HTTPS 及抖音域名后，由藏匣专用 Chrome/Edge 配置打开并激活网页。读取历史只剩 ID 时也可以尝试访问原页。该动作不承担下载、删除或更新来源状态的职责。基线实现见 [main.mjs](../../../electron/main.mjs)、[system-browser.mjs](../../../electron/system-browser.mjs)。

服务版建议由 Windows 默认浏览器打开经校验的官方原页，让网页使用该浏览器自己的抖音登录状态。NAS 会话专用于采集及下载。用户在藏匣内查看已归档图片、播放已下载视频则读取 NAS 媒体；原页下架或要求登录时，由网页反馈，藏匣保留已有资料。浏览器选择是本稿提议，待审阅。

### NAS 上的备份与恢复（0.4.1 提案）

“已下载”表示 NAS 媒体归档完成。“已备份”还需要一个能读回的恢复点。独立备份可放在另一块可独立恢复的存储设备上，Windows 日常使用无需承担备份。

**回收站验收。** 针对每个实际会执行可恢复删除的目标共享文件夹（含备份位置，如支持从那里删除）检查启用状态、访问权限和自动清理期限。通过正式服务运行身份、实际挂载和实际删除入口处理专用样本，确认绿联回收站可见、可恢复至原位置且内容摘要相同；仅在文件管理器里删除一次无法证明 Docker 服务路径也受保护。不支持、权限不足或无法核实时，停止该可恢复删除并保留文件，提示原因。作品的标签、来源关系、文件清单和删除范围由数据库另存恢复信息；移除一个归属时保留其他归属共用的媒体。参见[绿联回收站说明](https://support.ugnas.com/detail/article/zh-CN/159)。

**数据库升级。** 拉取镜像更新程序，持久卷保留资料。若新版需要改变 SQLite 的表或索引，先建立升级前的一致性副本并校验，再迁移结构。遇到空间不足、迁移报错或库版本不兼容时停止写入，显示具体原因，保留旧恢复点和现场库。使用一致性备份接口覆盖已提交的 WAL 数据。在独立目标用匹配版本打开恢复点并验证后，才由用户切换；升级后新增记录和媒体需先单独保护。这个恢复点覆盖业务数据库，媒体正文由文件备份负责。参见 [SQLite Online Backup API](https://www.sqlite.org/backup.html)。

| 用户遇到的事 | 处理方式 | 能恢复到什么程度 |
| --- | --- | --- |
| 误删一件作品或移错收藏夹 | 先查看本次操作的回收或恢复记录，预览要恢复的记录、归属与文件，再确认。只恢复这次选择的范围。 | 已保留原文件时可直接取回；若文件已彻底清除，需要从含该文件的备份中恢复。 |
| 拉取新版镜像后数据库升级失败 | 升级前建立一致的数据库快照，记录库身份、数据库版本、镜像摘要、文件清单及时间。到独立目标用匹配版本演练恢复；若升级后已有新数据，先保全增量，再由用户决定切换。 | 能还原当时的作品、标签、归属与任务记录。媒体原文件仍在且校验相符时可以重新关联；只备数据库无法补回缺失的视频或图片。 |
| 存放资料库的卷损坏 | 用事先存到独立介质的完整备份，在新卷恢复数据库与媒体，再核对文件大小和内容摘要。 | 恢复到最近一次完整且可读取的备份。只存在故障卷上的快照也会随卷丢失。 |

操作时先选择“仅资料库”或“资料库和媒体”、目标位置，预览预计空间与覆盖范围，再手动执行。完整备份把同一恢复点的媒体正文和清单一起保存，复制过程中变化或缺失的文件必须报告，不能将未核对的部分标为成功。完成后显示时间、目标、覆盖的作品与媒体数、缺失或失败项和校验结果。恢复先在独立目标核对，再选择是否采用；正在使用的库可继续保留。完整媒体副本所需空间通常接近所选媒体总量。是否把此手动备份功能纳入首版，待用户确认；定时备份及云服务仍属单独扩展。

## 执行与数据边界

1. **连接和持有使用权。** Windows 主进程通过已校验身份的 HTTPS 服务建立会话。NAS 原子裁定唯一持有者；无使用权时只能得到最小占用信息。未能确认有效使用权、电脑睡眠或发生切换时，锁住资料库、清除屏幕上的受保护内容并停止旧媒体流。重新进入须重新确认 NAS 状态。证书更换、库身份变化分别给出明确提示。
2. **来源身份。** 操作者通过 Windows 的受控入口查看 NAS 登录页面，在来源要求时亲自完成扫码或人工验证。核验 UID 后绑定资料库；来源账号和作品作者独立。会话配置受限持久保存，重启后优先核验现有会话。未登录、二维码失效、需人工处理、来源繁忙及浏览器超时有可区分的反馈。正式程序不提供通用远程浏览器控制。平台未触发的人工验证类型按实际覆盖情况标注。
3. **主进程与服务协议。** 沿用 renderer → preload → 主进程的调用边界，保留事件和可观察结果。正式主进程把资料查询、作业和持久修改交给 NAS，负责窗口、系统对话框、安全凭据存放和本机文件。大资料库从服务端分页，避免启动时向每台电脑整库复制。操作带库身份、会话代际、操作 ID 和相关版本；确认丢失时按 ID 取回执。客户端／服务协议或库版本不兼容时给出升级提示，保持已有资料可恢复。
4. **采集和任务交接。** NAS 在本机卷上的 SQLite 事务内提交完整页、索引所需业务数据、来源关系及排序、游标和回执。列表、详情、文件状态各有自己的更新范围。派生缩略图可重建；原业务要求的目录整理和 JSON 更新保存为独立可恢复的收尾状态。控制端失联后在安全页边界暂停采集；已发出的页先确定提交或放弃，未发出的页保留游标。接手者读取 NAS 断点，旧代际不能晚到覆写。
5. **文件和下载。** NAS 队列以作品与资源身份去重。临时文件、正式就位、校验、登记及必要整理均有持久状态，重启可区分“字节到齐”和“全部完成”。对路径重命名、删除和补齐做互斥及身份检查；未知同名文件保留待核对。来源地址刷新限定到对应作品。查询、播放和下载各有资源预算，切页/失联取消旧读取。窗口关闭后的 NAS 队列和仅本次运行的本机导出，各自按入口原意停止或继续。

## 交付、迁移和验收

- **版本与镜像。** 正式版从 `0.4.1` 开始，Windows 软件、NAS 服务和发布说明标注对应版本。正式 NAS 镜像预装浏览器、数据库及媒体运行时。一个 Docker 应用项目的常规镜像引用固定写为 `ghcr.io/wjh183322/cangxia-server:latest`。首版发布时先推送编号标签 `0.4.1`，在通过发布验收、核对镜像摘要后才将 `latest` 指向同一份镜像。后续版本保留各自编号和摘要，现场记录实际运行版本。用户新装或更新时在 Docker 项目中选择拉取最新镜像并启动或重新部署，沿用原持久卷；更新由用户发起。
- **启动与回退。** 正式启动校验挂载、库身份、写权限和数据库版本；区分首次建库、已有库升级、错挂卷。升级前保留可恢复快照，旧镜像无法读取新库时，使用匹配快照在独立目标恢复，单列升级后新增资料。正式版具备正常业务的快速/完整读取能力。试验样本上限、QA 密钥操作、手填 ID 验证页及故障注入只属于试验。旧版库、试验卷、正式库按身份隔离。
- **迁移。** 先停旧端写入，取得 Windows 活动库、旧 NAS 和历史恢复副本的一致快照；磁盘空间预检包含目标库、普通媒体、暂存和回退空间。只在独立目标做彩排。按作品、来源关系/次序、人工标签、共同作者、音频、任务和文件清单逐项对照。用大小及内容摘要核验媒体；明确删除受保护，旧副本独有及存在冲突的内容列候选。差异未解释前保留输入。正式切换需单独确认；切换后若需回退，先封存新增资料及任务，再恢复经过验证的旧端，避免两个写入端同时运行。
- **对照标准。** 建立以备份版页面和 IPC 方法、事件为索引的验收清单。每个入口记录输入、可见结果、NAS 和本机状态变化、失败／重试结果及证据；每项标注沿用、已批准映射或待解决。以同一份来源输入和相同窗口尺寸、缩放、筛选条件比较，单列不同时间实采造成的不确定性。正常、重复、并发、断线、磁盘失败、崩溃及重启均覆盖对应状态。
- **发布验收。** 安装正式 Windows 客户端及固定正式候选镜像，检查原布局、全部入口和业务结果。两台真实 Windows 分别做占用、退出、睡眠、断线重连和在途交接；LAN 与真实异地/Tailscale 分别记录列表、封面、视频首帧和拖动、并发读取下载与资源趋势。LAN 目标沿用列表 1 秒、首屏封面 2 秒、兼容视频起播 3 秒；外网单列链路和视频码率。用代表性 5 万作品数据及资料副本完成迁移与可用回退。资料丢失、越权进入、假报下载完成、错误文件覆盖、不可恢复删除或关键业务入口缺失，均阻断发布。
- **证据范围。** run-06 已验证 NAS 扫码后同账号重启恢复；固定双收藏夹样本已验证非零游标交接和单份媒体。慢二维码在受控测试中复现；真实强制短信验证未触发。原型观察和协议测试用于正式版回归，发布结论以正式候选实测为准。

## 决策归属

用户已选定完整版、沿用备份版客户端、NAS 采集与唯一正式库、预构建镜像及现有业务兼容原则；取消普通下载的本地归档目录入口，保留单独导出、临时缓存等本机目录。NAS 回收站须在实际位置和操作路径验证。本稿对原“仅本机移除”、打开原作品所用浏览器及手动备份范围提出建议，供此次审阅。接口命名、表结构、模块拆分、批次实现顺序、缓存预算和重试间隔由实施者依据原行为与实测确定。部署凭据、正式卷位置、镜像发布可见性及生产切换安排，在相应交付环节核对。

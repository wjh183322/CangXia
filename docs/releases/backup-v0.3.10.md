# 藏匣备份版 0.3.10

视频下载不再把低清封面直接当成高清单图。先比较平台实际提供的不同封面地址与视频实际分辨率；仍不足时，以现有封面匹配视频中的对应画面，按原始像素导出全帧或相同构图的裁剪区域。

没有固定 720/1080 的尺寸门槛。图片清晰度以视频本身为参照，不使用放大或 AI 生成填补细节。视频本身模糊时，截帧也不能凭空恢复细节。纹理不足、匹配不可靠、视频无法解码或超时，会显示“未取得与视频清晰度相当的封面”，保留原文件供重试。

原封面保留；增强图片以独立内容哈希文件名保存，来源标注为“平台高清封面”或“视频截帧”，记录实际尺寸及匹配时间点。全屏浏览优先展示选定的增强图片，保留视频浏览；原封面可在作品文件夹和详情图片列表查看。NAS 使用新媒体标识备份增强图片，不替换已有副本，服务协议仍为 2，无需部署服务端更新。

新下载的视频自动处理。旧作品可在“详情 → 补齐高清图”单独加入任务；也可用“补齐失败”列出旧封面待核对和失败的作品。高清处理沿用下载队列的暂停、取消、重试，不重新读取全部收藏，也不会因补齐封面而重新下载完整视频。

匹配组件打包在客户端内，无需用户安装 Python。视频分析在独立进程串行执行，限制为两个处理线程，最长约两分钟后结束；停止任务会终止对应处理进程。运行不上传图片或视频给 AI 服务。

验证：自动与桌面回归测试通过；匹配算法用生成的视频验证原像素裁剪、低于 720 像素视频、无关图片拒绝。已用实际样例验证：640×360 封面匹配视频第 0 秒并导出 1920×1080；480×360 原比例封面匹配约第 1 秒并导出 1439×1080。结果是截图匹配实测，不代表识别出了存图宝的内部算法，也不保证每个作品都有可匹配封面。

本次 Git 提交包含此前只在本机交付的 0.3.1–0.3.9 累计修复：空闲备份与断线恢复、封面定向补齐、大库响应优化、多任务下载、静默资源刷新、NAS 使用权修复、本地删除取消和下载取消。之前没有独立推送的逐版提交不会伪造为历史提交。最新安装包统一以 0.3.10 发布。

退出旧版后覆盖安装，保留资料与队列，无需卸载或清空缓存。

## 构建

在 Windows x64 安装 Node/Electron 项目依赖及 Python 3.12，执行 `scripts/build-cover-helper.ps1 -Python <python.exe>` 构建独立组件，再执行 `npm run dist`。Python 依赖版本记录在 `scripts/cover-requirements.txt`；分发包包含依赖许可文本。Python 匹配测试为 `tests/cover-frame-test.py`。

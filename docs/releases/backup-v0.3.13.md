# 藏匣备份版 0.3.13 / NAS 服务 0.2.1

NAS 备份页面新增删除功能：作品详情可单个删除，勾选后可多选或跨页全选批量删除。确认页显示所选数量和删除范围，确认后才向 NAS 提交请求。

删除所选作品的 NAS 视频、图片、高清图和云端封面预览，本地文件、收藏记录、作者作品关系和排序保留。NAS 同时保存停止备份标记，防止本机文件再次自动上传。仍被其他作品使用的文件保留；无引用文件会被安全清理，使用中或清理失败的文件稍后继续清理。此操作无法从藏匣撤销。

批量操作每批最多 100 个作品，显示进度和已释放空间，可停止后续批次并手动继续。已经提交的当前批次不能撤销。操作回执和进度持久保存，连接中断或客户端重启后先确认已提交结果，不自动删除后续作品。

本地作品详情和本地媒体库提供“重新启用 NAS 备份”，需要本机有媒体文件，并由用户再次确认。启用后在空闲时重新备份。其他电脑也会同步停止备份标记；旧客户端试图恢复已删除备份的写入会被服务端拒绝。建议所有备份客户端更新到 0.3.13。

## 升级 NAS：保留数据

1. 先暂停客户端当前任务。将 `CangXia-Backup-Server-0.2.1.tar` 上传 NAS；它已经是 `.tar`，不用解压。
2. 在 NAS Docker 的“镜像”中导入该文件，确认镜像名称为 `cangxia-backup-server:0.2.1`。
3. 打开现有 `cangxia-backup-server` 项目的 Compose 配置，只把 `image: cangxia-backup-server:0.2.0` 改成 `image: cangxia-backup-server:0.2.1`。
4. 保留原来的 `./data:/data`（或原绝对目录）、端口绑定 IP、18443:8443 映射及 `backup_net` 网络设置，然后重新部署。不要删除 data，也不要更换数据挂载位置。
5. 日志应出现 `CangXia Backup Service 0.2.1 ready (HTTPS, protocol 2)`。原密钥和证书保留，不需要重填。
6. 退出旧客户端，覆盖安装 0.3.13。重新检查 NAS 连接后即可使用删除功能。

协议继续使用 2。旧的 0.2.0 服务不提供此功能，客户端会提示先升级；正常浏览和其他同步行为仍可使用。

## 验证和构建

删除、跨电脑排除、共享文件保护、失去回执恢复、旧客户端写入保护、重新启用、批次取消和确认界面经过独立测试。Windows 安装包及桌面集成检查、Linux 服务镜像启动与测试由 GitHub Actions 完成；构建成功后才发布二进制文件。测试数据与用户实际 NAS 隔离，没有代替用户执行真实删除。

NAS 镜像使用 Node 24 和 OpenSSL，新增操作和清理记录保存在原 SQLite 数据库中。构建工作流与结果均可在仓库 Actions 页面查看。

# 藏匣本地版 0.2.5（预览）

针对“藏匣专用浏览器可读收藏，软件直接请求返回 HTTP 403”的已复现情况，加入浏览器页面读取方式。通过专用 Chrome / Edge 完成连接后，账号核验、收藏夹目录、总收藏、自建收藏夹与作品详情使用该浏览器页面发送请求，连续分页复用同一个页面。

## 在出现 403 的电脑上使用

1. 退出旧本地版，运行 `CangXia-Local-0.2.5-Windows-x64.exe`，保留原资料与下载目录。
2. 打开登录窗口，展开“网页能读但软件失败？使用专用浏览器”。
3. 点击“打开专用浏览器验证”，在该浏览器完成登录和抖音要求的验证，确认收藏可以正常加载。
4. 回到藏匣点击“我已在浏览器登录，连接”。如旧资料需要确认原账号，确认后继续。
5. 先读取少量收藏。读取期间保持专用浏览器开启，不要切换账号；中断后可使用“继续上次读取”。

通过专用浏览器连接后会记住此读取方式；重启软件后首次读取可能重新打开该专用浏览器。普通扫码和导入配置仍保留原请求方式；正常扫码小窗口与短信验证小面板保持不变。遇到直接请求 403，会明确提示使用专用浏览器连接，不再只建议反复扫码。

## 可靠性

- 读取前核对浏览器账号与当前资料库的稳定账号 ID，会话变化时重新核对；请求过程中会话变化的页面不写入资料库。
- 页面请求有超时、响应大小限制和取消处理，暂停会中止正在等待的请求。
- 浏览器关闭、页面关闭、超时或请求失败时保留已提交的数据及翻页位置。
- 收到访问频繁提示立即停止，不切换方式反复请求。没有生成或伪造请求签名。
- 切换到专用浏览器连接时取消原扫码流程，避免两条登录流程同时提交账号。

## 验证范围

用户诊断报告已证明问题电脑上直接请求为 HTTP 403，而浏览器页面请求为 HTTP 200 并返回 10 条记录。此次整合另使用独立测试目录及合成响应，在实际系统 Chrome 进程中验证连续 40 页、收藏夹目录与分页、暂停请求、断点续读和中途关闭浏览器；同时覆盖账号不一致、会话中途变化、超时、限流不回退等测试。

这不等于已在问题电脑验证全部真实收藏。升级后仍需在该电脑先试少量读取，再继续全量任务。NAS 版、备份版和 NAS 服务未改动。

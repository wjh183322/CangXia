# 藏匣备份版 0.3.4：同步响应优化

日志中主进程 RSS 曾达约 2.7 GiB。旧同步检查在窗口主进程重复解析整库、排序序列化与 SHA256 比较，无法及时处理窗口消息；每次状态变化还会重新生成整库临时对象。

此次将备份导出和哈希比较移到独立后台线程。线程使用只读 SQLite 事务取得一致快照，按 data_version 复用未变化的记录与哈希。主进程只接收需要处理的差异、待补封面及本机媒体对应的必要记录。健康记录不会因为不在差异批次中被误删，删除项由完整快照明确识别。

状态变化合并后异步检查，避免每次保存、点击都立即重复核算整库。批量提交复用已计算的哈希，继续保留幂等提交、丢失回执恢复及媒体完整性检查。备份服务仍为 0.2.0、协议 2，不需要重新部署。

问题作品扫描改成逐条读取并定期让出事件循环，不再一次保留全部大记录。界面操作增加即时重复点击保护，主进程也拒绝重复的同名未完成操作。

## 当前资料库只读测量

- 59,291 条记录及关系。
- 旧整库比较总耗时约 3,218 ms，主线程定时器最大间隔约 3,234 ms。
- 新后台线程冷检查总耗时约 3,278 ms，主线程最大间隔约 27 ms。
- 缓存后的重复检查约 69 ms。

上述结果来自本机独立进程对用户资料库的只读测量，没有请求抖音或写入用户数据库。总网络备份时间仍受带宽、Tailscale 中继和文件数量影响；该指标证明这段核算不再连续阻塞主线程，不代表所有场景都无卡顿。

247 项自动化测试、44 项界面检查、24 项真实桌面检查通过。包含后台哈希与原规范一致、显式删除保护、事务变化识别、主事件循环响应、作者顺序、停止续读、断线续传和提交回执恢复。打包线程运行与源文件一致性在交付时复核。

保留现有数据和缓存，退出旧版后更新客户端即可。

# 藏匣备份版 0.3.39

修复 0.3.38 对真实抖音错误页面的漏判，继续配套 NAS 0.2.4。保留已有读取记录、本机文件、缓存和 NAS 备份。

- 识别实际页面的 `error-page` 官方错误区，支持“不存在”文字及操作使用 P 标签的结构，不再只等待链接或按钮。
- 网页复核允许复用静态资源，减少重复加载。对应作品文档或详情出现缓存证据时，关闭旧临时页后实时复核一次，共用原来的总超时；证据不足仍保留未知。
- 继续保护登录、验证码、限流、网络错误、其它作品、评论推荐文字和未完成的详情请求。失效判定不删除文件或 NAS 副本。
- 记录单次复核的耗时和阶段，区分网页尚未加载、未找到有效提示、详情尚未完成等情况，便于定位超时。诊断不保存网页正文或 Cookie，沿用现有日志轮换。
- 接口成功且详情为空、原因也为空，仍需补充证据；不会仅凭 `status_code: 0` 或 null 宣告作品失效。图文不出现 `aweme/detail` 请求也不是失效依据。

两种核验方法及图文样本研究见[对照研究](https://github.com/wjh183322/CangXia/blob/codex/backup/docs/research/2026-10-21-source-verification-method-comparison.md)。隔离浏览器与真实匿名页面观测不能替代遵义电脑的已登录账号验收。

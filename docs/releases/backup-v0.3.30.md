# 藏匣备份版 0.3.30

修复读取日志“打开抖音作品”报“作品选择无效”的问题：界面向后台传递经过验证的作品 ID；日志仍保留而当前作品记录已移除时，也可以使用该 ID 打开官方作品地址。

读取总结、全部日志、单轮日志及收藏读取窗口统一采用五项统计：本轮读取、前面新增、本轮补齐、本轮新增、已有记录。本轮读取按作品 ID 去重，包含新旧作品；本轮新增为前面新增与本轮补齐之和。前面新增仅指本轮第一条已知作品之前的新记录，遇到已知作品之后首次取得的作品计为本轮补齐，均以当前收藏夹或作者列表为范围。

历史作品再次读到单独显示、单独筛选，归入已有记录，不重复计入补齐或新增；这个标记不代表作品曾失效或恢复播放。首次建立整个列表的资料时单独标注首次读入，不强行拆分前面新增和补齐。已有旧日志在展示时兼容转换，保留原始归档数据；统计版本标记避免重复转换。仅保存过读取数量的旧版未完成进度保留原数，没有记录的分类显示“未区分”。

例如旧日志“读取 1107、前面新增 266、补齐 294，其中历史重新返回 1”，现在显示为：本轮读取 1107、前面新增 266、本轮补齐 293、本轮新增 559、已有记录 548，其中历史记录再次读到 1。另一轮读取 205、前面新增 128，显示本轮补齐 0、本轮新增 128、已有记录 77。

每条差异记录新增“在列表里显示作品”：进入该轮所属的收藏夹或作者列表，清除筛选、翻到作品所在页、滚动并短暂高亮，保留相邻作品和保存顺序，不打开详情或播放器，也不勾选下载。读取刚结束、列表通知尚未到达时会先重新获取本机列表快照，避免误报作品已移除；正常定位直接使用当前快照。定位显示当前保存的列表位置，可能与日志中的当轮读取位置不同。已移除的列表或作品会说明无法定位，日志保留，不自动恢复或更改排序。

日志按每页 50 条加载，定位使用已加载的列表索引，不重新读取整库、不扫描全部媒体文件。小窗口的读取总结和日志保留固定头部及底部按钮，内容单独滚动。

连续 60 条历史顺序匹配、至少跨两页的检查新增停止规则不变；历史作品继续保留，读取不自动下载，NAS 服务仍使用 0.2.3。退出旧程序后覆盖安装即可，无需清缓存、清库或重新读取。

验证覆盖历史重新返回与新增分离、首次建库、旧归档不改写、重复转换、旧版断点数量、收藏及作者定位、清除筛选与后页定位、缺失作品提示、原作品 ID 参数及无本机记录的日志链接。用户提供数据库仅通过隔离只读副本核对两轮历史数据，未写入原文件。真实 Chromium 以 30,415 条合成记录验证定位到第 1,501 页及相邻作品，并核对 1100×640 小窗口的日志和五项总结；合成数据不代表已在遵义完成新版现场读取。

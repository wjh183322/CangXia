# 藏匣备份版 0.3.31

修复媒体地址跳转时报“Redirect was cancelled”导致下载失败的问题。Electron 的手动 fetch 在跳转时无法读取 Location，本版只在出现该错误时通过 ClientRequest 读取跳转响应头，逐跳验证地址后继续流式下载，保留 Range、If-Range、请求取消与最终资源地址。瞬时网络错误和部分服务端错误每个资源最多自动重试两次；资源过期仍只定向刷新这一条作品。批量补齐的封面与元信息也使用后台刷新并传入停止信号，登录失效时保留进度，不自动打开公开作品页面。平台限流和登录失效暂停下载，磁盘与权限错误停止当前任务并保留已保存内容。

普通下载管理分为“正在下载”“下载失败”“已下载”三栏；失败栏支持单个、所选及全部失败任务重试，全部操作覆盖所有分页。重试保留任务原来的抖音／NAS 来源以及普通下载／高清图补齐类型。单项重试后清除其旧选择，失败页取消操作只作用于仍然失败的任务。

“补齐失败”入口改为“检查与补齐”，窗口名称为“作品检查与补齐”。处理状态可筛选待检查、待补齐、处理中、下载失败、补齐失败和已补齐；问题类型包括封面、缺损文件、视频缺失、图文图片缺失、文件异常、作品信息不完整和无法检查。每个类别显示数量，同一作品按 ID 去重。

问题作品按当前保存的收藏顺序从新到旧排列，不按作品发布时间或作品 ID 排序。没有总收藏位置的作者作品与其他保留作品排在后面并显示来源。支持“全选当前筛选结果”，以本轮检查令牌、筛选条件和排除项在后台解析全部分页；切换筛选会清空旧选择。只处理封面问题、下载失败及曾下载过的缺损文件，未曾下载的正常作品继续使用普通下载入口。

文件检查在 worker 中执行，补齐阶段也分批通过 worker 重新确认文件，逐项让出主线程。列表每页 20 条、下载队列每页 50 条；小窗口固定显示底部操作按钮。检查途中可以停止，已查出的部分问题保留并说明尚未完成全量检查。后台检查失败或超时会暂停任务，未检查的作品不会被标成已补齐。

补齐结果持续跟踪交给下载管理的任务，区分排队、下载中、已补齐和失败。下载完成／失败会将终态写入本机补齐任务库；清空下载历史或重启程序后仍保留补齐结果。已保存的完整文件会跳过，只补缺失内容；取消下载只影响队列，收藏、作者作品记录与 NAS 副本保留。

验证包括真实 Electron 的连续跳转、续传请求头、地址验证和 429 暂停；大列表分页、跨页全选及排除项；原来源和高清图任务重试；检查／补齐途中停止；worker 失败；下载完成后清空历史并重启的结果持久性。另用 7,541 条合成问题记录验证 1100×640 小窗口布局与批量操作。自动化与隔离实验不代表已在遵义现场验证所有真实失败作品。

NAS 服务仍为 0.2.3，无需升级。退出旧程序后覆盖安装，保留原有资料、下载队列和补齐进度，无需清缓存或重新读取。

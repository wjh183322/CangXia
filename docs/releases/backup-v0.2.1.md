# 藏匣备份版 0.2.1 预览

修复仅“读取收藏”、没有下载作品媒体时，清空本机缓存后从 NAS 恢复记录却看不到封面的问题。

此前同步保存了作品记录中的封面网址，但没有独立备份封面图片；只有已备份的作品媒体可以用于恢复封面。现在同步时会优先使用本机封面缓存，为尚未保存的封面获取图片、校验并上传到 NAS。全新的电脑无需先登录抖音，也能从 NAS 显示已成功备份的封面。

- 封面单独关联到作品记录，不计入普通下载历史、本地媒体库或“NAS 备份”的完整作品数量。
- 与备份服务 0.1.0、协议 1 兼容，**现有 Docker 无需更新或重新部署**。
- 无法取得封面的作品仍可同步文字记录；状态显示“封面待备份”和待处理数量，避免误认为封面也已保存。
- 封面请求并发上限为 3，每张上限 20 MiB；只接受支持的图片格式，先上传并校验对象，再提交引用。
- 保留同步期间的本机修改，提交确认丢失后可恢复，不因补封面覆盖正在修改的作品资料。

## 现有记录如何补齐

1. 退出旧版，打开本版，保留现有缓存和数据。
2. 在设置中点击“立即同步 / 换电脑前同步”。已有有效缓存或仍可用的网址可用于补齐封面。
3. 若显示“封面待备份”，重新登录抖音并重新读取对应收藏夹以更新资源网址，然后再同步。
4. 确认同步完成、待备份封面为 0 后，再做清空本机缓存或换电脑的恢复实验。

新版本无法凭空恢复此前从未备份且原网址已失效的图片。无需再次清空 NAS，也不需要为了封面下载整部视频或整套图文。

## 验证

通过 166 项单元测试、界面回归、原备份桌面流程，并新增实际 Electron 恢复测试：只创建读取记录并备份封面，在另一个完全空白的配置目录重新连接 NAS，不导入抖音登录信息，确认封面可解码且没有新增媒体下载记录。同时验证总收藏两页、自建收藏夹独立顺序、停止部分读取后的恢复，以及只读自建夹时保留“待确认”分组；封面处理顺序不影响作品排序。修复多个作品使用相同封面时 Windows 并发写缓存的冲突。测试使用隔离目录、HTTPS 测试服务和合成图片。

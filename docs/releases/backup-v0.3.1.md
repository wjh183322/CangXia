# 藏匣备份版 0.3.1

此次更新修复读取期间自动备份与断线收尾问题。客户端更新为 0.3.1，NAS 服务仍使用 0.2.0、协议 2，无需重新部署或删除数据。

## 使用行为

- 读取收藏、核对新增、读取作者及查询作者信息前，先暂停已有 NAS 上传并等待它退出。
- 读取和下载期间不启动新的备份；读取结束或下载批次结束后，在空闲状态自动同步。
- 读取过程中 NAS 临时断联，已开始的任务仍可写入本机、提交页面、保存顺序及续读位置。读取结束后解除这个限定的本机写入范围。离线时不能直接开始新读取或修改其他资料。
- NAS 恢复后重新比对记录；双方有修改时进入冲突状态，不覆盖本机或 NAS。
- 上传中断后先查询服务器保存的偏移，再续传；提交回执丢失时复用同一个 request ID，避免重复提交。
- 证书指纹不匹配、权限错误及其他非网络错误不作为短暂网络故障自动重试。
- 真实的收尾保存失败显示具体错误，并记录诊断，不再一律提示磁盘空间或权限。
- “本机有更新”改为“本机资料待同步”；增加“等待空闲备份”。

## 本次故障调查

2026-10-06 本机读取保存了 21,988 条作品、1,474 页，最后页面提交时间为北京时间 13:11:53。数据库 quick_check 正常，资料目录写入检查正常，C 盘余量约 25.5 GiB。NAS 上传界面显示 ECONNRESET；旧版 unavailable 回调停止读取，随后写入权限检查拦截读取收尾，错误被通用磁盘提示覆盖。

对现有 NAS 的只读 /healthz 做连接复用试验：旧版传输器完成预热后，单独测试进程阻塞 6.5 秒，随后请求返回 ECONNRESET。新版同样试验记录 reusedSocket=true、receivedHeaders=false，在新连接重试后返回 HTTP 200、protocol 2。测试未修改 NAS 数据或配置。

该试验复现了旧版对失效 keep-alive 连接缺少重试的机制，不能追溯证明原始事件唯一由此触发。原有日志未保留失败请求阶段、连接复用状态或服务启动时间。用户在故障后重启服务，此次重启不能当成之前错误的原因。

当前 Tailscale 连通性检测经 DERP(lax) 中继约 366 ms，未建立直接连接。这是传输延迟证据，不是原始 ECONNRESET 成因的证明。

新版诊断增加 nas-request-error、nas-request-retry、nas-unavailable、nas-paused-for-read、read-save-failed。记录请求类别、方法、错误码、连接复用标记、是否已收到响应头和耗时；不记录访问密钥、凭据或文件正文。

## NAS 网络部署

本次发现旧备份容器没有连接任何网络，容器内部 healthz 正常，但访问 NAS 地址报 ENETUNREACH。明确连接 backup_net bridge 后，现有 NAS 的远程 HTTPS healthz 恢复 HTTP 200。部署模板已增加明确的 bridge 网络声明。

现有 NAS 已修复，不需要为了客户端 0.3.1 再部署。新部署仍使用原有镜像 0.2.0。需要同时绑定局域网与 Tailscale 的 NAS，可使用已验证的双地址端口映射；必须确认 Tailscale 使用 host 网络和内核模式，并保留 data 挂载及现有证书。

## 验证与实际使用边界

回归覆盖：空闲调度、正在上传时开始读取、读取中断联继续提交、断联后手动停止与续读、恢复连接后的双方冲突、真实 HTTP 复用连接重置、服务器已接收部分数据但回执丢失后的精确续传、丢失提交回执的幂等恢复、初次申请写入权不盲目重试、日志凭据排除。

已通过 230 项自动化测试（其中 10 项为新增故障回归）、40 项界面检查、22 项真实 Electron 桌面检查和 8 项新电脑恢复检查。尚需用户用实际账号再次核对全部收藏，验证完整读取与大量封面备份最终完成；上述测试不代表已证明真实账号的全部收藏数量。

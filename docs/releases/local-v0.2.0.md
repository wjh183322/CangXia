# 藏匣本地版 0.2.0（预览）

本版在 `codex/local` 上从本地版 0.1.7 演进，不引入 NAS 服务或备份版的同步依赖。

## 大库处理

- 使用 Electron 内置的文件型 SQLite 和 WAL，读取每页只提交变化，取消每次整库导出与整库备份。
- 第一次升级旧库时创建 `library.sqlite.pre-local-0.2.0` 一致性备份，保留原来的收藏、下载、标签和登录文件。
- 缓存已转换的界面记录；通过增量记录和顺序差异更新界面，状态变化不再反复发送全库；首次大库状态分块传给界面，对更新版本不一致的情况自动重新获取完整状态。
- 读取记录和翻页进度在同一事务提交；异常退出后可在读取窗口选择“继续上次读取”。

## 登录与访问提示

- HTTP 401/403、无效返回和平台业务访问提示会显示重新登录/完成验证入口，停止重复读取并保留已提交记录。
- 使用经过核验的稳定账号 ID，提供专用 Chrome/Edge 验证和“我已在浏览器登录，连接”入口。
- 旧版本没有保存稳定账号 ID、且 Cookie 已变化的总收藏库，可能需要用户明确确认当前扫码账号是这些记录的原账号，不静默改绑。
- 增加脱敏的状态码、进程异常和内存诊断记录；不保存 Cookie 或完整接口响应。

## 升级操作

完全退出旧本地版，再运行 `CangXia-Local-0.2.0-Windows-x64.exe`。继续使用 `%APPDATA%\藏匣` 和原下载目录，不删除缓存、不迁移到 NAS。标题栏显示“藏匣本地版 v0.2.0”。

如出现访问提示，先点击“重新登录 / 完成验证”。扫码后若仍需验证，打开专用浏览器完成正常登录和平台验证，再点击“我已在浏览器登录，连接”。平台限流或验证要求不会通过本版绕过；若仍失败，可从设置打开 diagnostics 目录查看脱敏代码。

旧版已有的 22,816 条等记录没有保存翻页游标，无法凭数量反推出断点，第一次仍要从头核对。新版创建的后续读取进度才可续读。长时间中断后平台游标可能失效；收藏在暂停期间变化时，续读完成后建议从头核对。续读不会把未再次遇到的旧记录直接当作删除。

SQLite 新增 WAL/SHM 辅助文件。程序运行时不要只复制或删除主数据库文件；备份整个配置目录前先退出程序。不要让旧版和新版同时访问同一库。回退时先保留当前完整目录，再使用升级前的一致性副本，而不是直接用旧版覆盖新库。

## 验证与性能边界

使用一份 22,816 条记录、约 227 MiB 的只读来源副本，在独立进程进行单次对照：

| 指标 | 0.1.7 | 0.2.0 |
|---|---:|---:|
| 更新 30 条后的界面更新包 | 约 33.1 MiB | 约 35.7 KiB |
| 同一更新阶段耗时 | 约 1704 ms | 约 85 ms |
| 该阶段进程 RSS 采样 | 约 1197 MiB | 约 252 MiB |
| 保存 30 条更新 | 约 364 ms | 约 8 ms |

上述是本机副本的单次处理测试，不是线上抖音吞吐测试或整机峰值承诺。首次升级创建备份有额外开销。真实平台登录、账号验证及接口变化仍需在用户环境确认。

测试覆盖旧数据库保留、事务中断恢复、页面回滚、半页续读、重复请求去重、状态更新一致性、访问失败后重新登录续读，以及桌面端实际界面更新。NAS 版、备份版和 NAS Docker 未修改。

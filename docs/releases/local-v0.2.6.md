# 藏匣本地版 0.2.6（预览）

二维码弹窗登录、配置导入和专用浏览器登录现在统一接入后台浏览器读取。正常使用不再需要保留 Chrome / Edge 的登录窗口；保留原来的扫码小窗口与短信验证面板。

## 使用

1. 退出旧本地版，运行 `CangXia-Local-0.2.6-Windows-x64.exe`，保留原资料和下载目录。
2. 使用原来的二维码弹窗登录，按抖音要求完成必要验证。
3. 先试读少量收藏，确认正常后继续上次进度或完整读取。
4. 如平台仍要求在浏览器验证，可展开“需要进一步验证？打开专用浏览器”，验证后点击“连接”。登录窗口随后自动关闭，读取在后台继续。

电脑需要安装或启用较新的系统 Chrome / Edge。后台仍有浏览器进程，并非零内存开销；空闲约一分钟且没有用户打开的专用浏览器页面时会释放进程，下次读取按需重建。

## 改动

- 扫码成功后，仅将当前抖音域的登录会话交接到软件自己的浏览器资料目录，不读取用户日常浏览器的其他网站凭据。
- 交接后先通过浏览器页面核对稳定账号 ID，验证通过后才写入账号绑定并读取收藏；不同账号和请求期间的会话变化仍被拒绝。
- 系统 Chrome 使用隐藏读取页面，正常读取没有可见标签页或浏览器窗口，不改写 User-Agent，不实现或伪造签名算法。
- 部分 Chromium 版本在冷启动时需要先有一个页面：必要时短暂创建一个最小化的空白引导窗口，后台页面建立后立即移除。它不会打开抖音或要求用户保留窗口。
- 后台进程意外退出会保留断点，点击继续读取可重建；不会误把进程退出当成账号登录失效。
- 登录完成后自动关闭用于登录的专用窗口；用户主动打开的作品页面不会被空闲清理强制关闭。
- 保留访问频繁时停止、请求超时、取消和已有收藏数据保护。左上角及设置版本号同步为 0.2.6。

## 验证与限制

独立目录和合成数据测试覆盖：真实系统 Chrome 的隐藏页面无窗口、二维码会话交接、连续 40 页、收藏夹分页、关闭登录窗口后继续读取、暂停续读、进程退出后的重建、空闲释放与再次读取、账号变化及限流不回退。没有使用真实账号发送测试短信。

这解决了“二维码登录仍走旧直接请求”和“必须留着登录浏览器窗口”的实现差异。问题电脑上的真实平台读取仍需复测；不能保证平台永远不会要求额外验证。关于两台电脑差异的证据与未确定事项，见[403 调查记录](../investigations/http403-2026-09-21.md)。

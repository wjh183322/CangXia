# 藏匣备份版 0.3.2

修复已有封面仍反复请求 NAS、封面下载连接重置后不重试，以及补封面结束后残留“准备封面”进度的问题。NAS 服务继续使用 0.2.0、协议 2，无需重新部署、重新读取收藏或删除缓存。

## 调查结果

2026-10-06 当前本机保存 29,607 条作品及对应收藏关系，完整核对在北京时间 15:06:34 到达当前可访问列表末页，共 2,699 页。当前备份基准 revision 为 66，dirty=false、无 pendingCommit，29,606 条作品有已提交的备份封面引用。

本机 covers/previews 已有 29,580 个按内容哈希去重的封面文件，共 9,401,823,568 字节；covers/backup 只有 36 个。0.3.1 的取封面路径忽略准备备份时生成的本机 previews 缓存，选择 NAS 下载；日志显示 GET /v1/objects 多次出现 ECONNRESET、reusedSocket=true、receivedHeaders=false，但 download 当时没有使用 json/upload 的自动重试机制。这能解释已有封面的一批卡片仍无法显示。

“封面待备份；记录已同步，1 张封面待备份”表示记录和其余已备份封面已经提交，只剩一张未取得。该作品保存的 p3-pc-sign.douyinpic.com 与 p9-pc-sign.douyinpic.com 图片地址在本次只读探测中都返回 HTTP 404。这不证明作品已删除，也不表示整批未同步。

## 修改

- 已有备份封面首先使用本机准备缓存，其次使用本机 NAS 缓存及原有 ID 缓存。显示前核对长度和 SHA256，错误内容不冒充有效封面。
- 本机有正确缓存时，即使 NAS 离线也显示封面，不创建下载任务或媒体保存记录。
- NAS 图片和媒体下载遇到短暂连接重置，最多重试两次；已有片段通过 Range 继续，完整文件仍核对长度与 SHA256 后才采用。
- 同步没有新记录可提交时，也清除已结束的准备进度；补封面失败的提示不再无条件要求重新登录。
- 不更改原图、视频、收藏顺序或 NAS 数据。

## 验证

故障回归包含离线显示本机准备缓存、同长度损坏缓存回退、损坏 NAS 缓存离线拒绝显示、下载收到部分正文后连接重置并精确续传。当前用户数据库的首屏 20 条作品已通过新取封面逻辑，只读验证全部 20 张本机封面 SHA256 匹配，无 NAS 请求或数据库写入。

已通过 234 项自动化测试、40 项界面检查、22 项真实 Electron 桌面检查和 8 项新电脑恢复检查。仍需用户安装新版查看实际页面；一张 HTTP 404 封面的来源后续若恢复或取得新地址，可再次补备份。

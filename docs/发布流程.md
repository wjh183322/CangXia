# GitHub 发布约定

仓库：`wjh183322/CangXia`，公开。

这是独立的新仓库，源码位于 `main` 分支，每个版本使用 `vX.Y.Z` 标签。

每个程序版本使用独立 GitHub Release。程序文件名必须包含版本号，例如 `CangXia-0.1.1-Windows-x64.exe`。二进制放在 Release 附件，不能提交进 Git 历史。

## 新版本

1. 更新 `package.json`、锁文件、设置页版本和变更记录。左上角标题栏版本由构建自动读取 `package.json`，不再手写。
2. 编写 `docs/releases/vX.Y.Z.md`，说明变化、验证结果和已知限制。
3. 运行测试并构建程序，完成本地验收。发布前必须核对左上角标题栏、设置页、程序文件名和版本标签一致；`test:nas-desktop` 包含标题栏、页面标题与版本信息的一致性检查。
4. 提交源码，创建与该版本源码对应的标签。
5. 在已登录 GitHub CLI 的环境运行：

   ```powershell
   ./scripts/publish-release.ps1
   ```

脚本校验版本、标签与工作目录，并上传程序和校验文件。已存在的 Release 不会被覆盖。

## 历史版本

v0.1.0 归档现存的原始程序，不冒称保留了完整开发源码。它的标签只包含归档说明。v0.1.1 起的标签对应实际提交的源码。

## 排除项

不得上传 `.test-output`、账号会话、Cookie、数据库、媒体库、日志、样例下载素材或凭据。发布前核对暂存区与程序包内容。

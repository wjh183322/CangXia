# 空详情响应与图文跳转的进一步核实

日期：2026-10-21。本文补充并修正此前[方法比较](2026-10-21-source-verification-method-comparison.md)中“空原因过滤响应尚未确认语义”的结论。本轮是只读研究，未修改 0.3.39 的正式判断逻辑。

后续实施：用户确认仅使用 JSON 后，0.3.40 已按本文证据增加严格空过滤组合判断，并删除网页复核实现。实现和本机验证见[JSON 核验记录](2026-10-21-json-only-source-verification.md)。以下“未修改”“建议”等描述保留的是最初研究阶段的范围。

## 新结论

抖音当前官方网页代码确实把业务状态为 0、但没有作品详情的结果转换为内部 `ERROR_404`；视频界面再据此显示“你要观看的视频不存在”。内部错误值是 -404，接口原始 `status_code: 0` 本身仍表示调用成功。

因此，不能再笼统地说用户给出的完整空原因过滤响应“完全没有可用于判断的证据”。现在已有官方处理逻辑与真实负例相互支持，可以据此设计“当前不可访问”的严格接口规则；这不证明作品已永久删除。

建议规则同时要求：HTTP 请求成功、JSON 结构有效、业务状态为 0、`aweme_detail` 明确为 null、`filter_detail.aweme_id` 与目标完整一致、过滤原因为空，且没有登录、验证、限流或异常提示。已验证的权限、审核、隐私返回继续保留各自原因。单独出现 null、没有收到接口、超时、ID 不符或响应无法解析，仍不能按该规则判定。

这是对当前网页行为的实证和实现建议，不是平台提供的长期接口规范；未来返回结构变化仍需维护。

## 官方网页代码的证据链

以下均为本次从抖音页面加载地址读取的公开静态脚本，未使用第三方接口解释：

1. [详情转换模块](https://lf-douyin-pc-web.douyinstatic.com/obj/douyin-pc-web/ies/douyin_web/client-entry~192ceba9.cfe4d023.js)，模块 649397：详情接口是 `/aweme/v1/web/aweme/detail/`。转换函数保留非零错误码；业务状态为 0 时，有详情则返回成功，无详情则转换为 `ERROR_404`。另将该组合标为 `isUnknownAweme`。
2. [错误常量](https://lf-douyin-pc-web.douyinstatic.com/obj/douyin-pc-web/ies/douyin_web/client-entry~0.28149745.js)：`ERROR_404` 为内部 -404，与接口状态 0 不同。
3. [视频错误界面](https://lf-douyin-pc-web.douyinstatic.com/obj/douyin-pc-web/ies/douyin_web/client-entry~6f4ee80d.40c52456.js)，模块 555504：内部 404 对应用户截图中的视频不存在提示；其他错误另有服务器或账号等提示。
4. [视频路由](https://lf-douyin-pc-web.douyinstatic.com/obj/douyin-pc-web/ies/douyin_web/async/routes-Video-id-route.a7450dc7.js)，模块 294650、28675：获取详情后，若类型是 Note，通过 `window.location.href` 转至同 ID 的图文地址。因此会发生整个文档切换，开发者工具未勾选“保留日志”时，前一个页面的请求可能从列表消失。
5. [图文路由](https://lf-douyin-pc-web.douyinstatic.com/obj/douyin-pc-web/ies/douyin_web/async/routes-Note-id-route.27436ca1.js)，模块 333829：非爬虫路径使用同一详情模块，并指定 `NotePage` 来源；页面可先使用传入的初始详情，缺失或 ID 不匹配时再请求。因此不能要求每次打开 note 都在浏览器 Network 中重新出现详情 XHR。其内部 404 提示为“你要观看的图文不存在”。

这些代码支持 video 与 note 共用详情接口及空详情的错误转换。图文的正向判断仍应检查匹配 ID 的图片资源；不能以缺少视频播放地址为失效依据。

## 真实请求与对照

使用新建的隔离 Chrome 配置，未登录、未读取用户原有浏览器资料。捕获器在导航前启用，跨文档保留请求和响应摘要，只记录路径、必要的普通参数、状态及资源数量，不保存 Cookie、鉴权字段或签名 URL。

- `7682371267983207909`：一次页面自行发出的详情 XHR 返回 HTTP 200、业务状态 0、详情 null、对应 ID 的过滤对象及空原因；响应 165 字节，约在导航后 2.58 秒读完。之后页面跳到精选。该空响应与用户此前提供的负例一致。
- 图文 `7698014329241074098`：在正常官方页面环境发起普通只读详情请求，返回 HTTP 200、业务状态 0、完全匹配的作品 ID、`aweme_type: 68` 和 1 张图片。该次响应 25,374 字节，现有解析器判断为可访问。
- 可播放视频 `7689084254681498725`：相同方式返回 HTTP 200、业务状态 0、匹配详情和媒体资源，类型 0，现有解析器判断为可访问。该次响应 64,436 字节。

后两项是研究主动发起的普通页面 fetch，不能称为“自然页面加载已经捕获到跳转前的 XHR”。其签名等由官方页面自身处理，没有自行构造或复制签名、读取用户 Cookie 或绕过登录验证。

另在同一个新建匿名页面会话内，直接复用藏匣当前 `apiRequest` 的参数生成函数进行了三条作品的对照：正常视频返回完整视频详情；正常图文返回完整图文详情；负例仍返回对应 ID、空原因的过滤响应。对该图文另加 `origin_type: note_page` 也取得完整详情。这排除了本次样本仅因使用 `video_page` 参数而让图文详情为空的猜测，但不将三个样本扩展为所有账号和作品的全量验证。脱敏的四次对照及官方脚本 SHA256 见[证据摘要](2026-10-21-empty-detail-and-note-evidence.json)。

## 跳转的验证边界

藏匣现有 `parseWork` 对所有作品保存 `/video/ID` 链接，`openOriginal` 使用保存的链接；这解释了为什么从藏匣打开图文先进入视频地址。官方路由中的类型判断与用户观察到的 video → note 一致。

本次匿名端到端页面访问有多次未能完成静态脚本加载，停留在“视频数据加载中”；未完整复现这条图文的自动跳转。因此，已确认的是官方跳转逻辑和该图文的真实详情接口，不把源码证据写成已复现整个跳转过程，也不把加载不全归为作品失效。

如需在遵义电脑补齐自然跳转的证据：打开开发者工具 Network，先勾选“保留日志 / Preserve log”，再从 `/video/7698014329241074098` 开始；筛选 `aweme/detail`，只取 `aweme_id` 相同的响应。刷新或跳到 note 后也保留之前的记录，不需要重新读取资料库。

## 两种方法的取舍

建议接口为主：匹配详情及资源确认可访问；明确权限等返回按原因处理；上述严格空过滤组合按当前不可访问处理。网页只复核剩余证据不足的情况。这样可以减少这组空原因负例每条再等整个网页加载的成本。

网页仍适合确认界面提示与调查平台变化，但受脚本加载、跳转、登录及 DOM 变化影响。图文已经实测支持同一详情接口，目前没有必要先开发一套复杂的初始 HTML 状态解析器来替代它。

最初研究结束时的 0.3.39 尚未采用新增严格规则。后续 0.3.40 的实施另行记录，不能将最初匿名探针的观察视为完整用户账号验收。

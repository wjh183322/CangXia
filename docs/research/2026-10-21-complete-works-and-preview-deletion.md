# 完整作品的问题归类与 Windows 预览句柄调查

日期：2026-10-21。桌面修复版本 0.3.42，NAS 服务仍为 0.2.4。

## 完整作品仍留在问题总览

用户要求：本地文件已经检查完整、没有实际文件或任务问题时，即使原作品现在无法观看，也不应继续出现在“问题总览”。原作品状态仍需在正常列表和详情中提示，删除文件时提醒无法从原作品重新下载的风险。

旧投影把原作品失效或暂无法确认本身也作为问题，因此文件完整的作品仍显示“无文件问题”，同时占据问题总览。这两个状态各自并不矛盾，但总览的收录规则不符合用途。

新规则优先采用已经确认的文件完整度：只有文件事实明确完整、文件处理状态完整，并且没有封面缺损、任务失败等其他问题时，原作品状态不再单独使它进入问题总览。只有来源信息而没有实际完整文件证据的记录仍保留；失败任务和真实文件缺损仍保留。原作品状态事实不删除，本轮检查历史不清空。

旧的持久化问题索引在准备总览时分批重新投影，仅处理之前文件状态完整的问题记录，并保存一次性策略版本。此步骤不自动检查全库文件、不访问抖音、不重读收藏。

## 删除提示权限，关闭藏匣后可以删除

用户最终确认：藏匣运行时，在软件和资源管理器里都无法删除；关闭藏匣后可以删除。这个更正替代了之前“关闭后也失败”的描述。用户目录位于另一台电脑，没有修改该目录的权限或文件。

在当前 Windows 上以隔离临时目录复现：通过 Electron `net.fetch(file:)` 向 Chromium 提供预览，保留未读完的响应后，目录移动返回 EPERM；中止该响应并取消底层 reader 后，同一进程内立即移动成功。失败与恢复均检查实际文件系统结果，不只检查命令退出码。测试没有清空回收站、修改 ACL 或申请管理员权限。

Windows 原生回收站调用可能弹出权限提示，因此该提示本身不能证明需要修改 ACL。Electron 的 [Windows 实现](https://raw.githubusercontent.com/electron/electron/v44.3.0/shell/common/platform_util_win.cc)使用 IFileOperation，并允许显示提权提示；这与实测句柄占用可以同时出现。

修复统一管理本地封面、视频、图文、配乐等文件预览响应。删除所选作品前先阻止新预览、等待现有响应和缓存引用释放，再执行原有队列与配乐退出检查。其他作品继续读取。独立“删除本机配乐”也执行同样的句柄释放，但门禁仅作用于音频，同一作品的封面继续可读。正在播放及共享配乐引用的原有保护保持生效。

如果释放失败或超时，不执行后续删除。真正删除失败时保留未完成步骤，界面显示具体错误；如果 NAS 已成功、本机失败，保留 NAS 回执，重试只执行未完成步骤，不重复删除 NAS。删除确认文字分别说明本地、NAS 或双方副本的范围，以及原作品不可观看时删除最后副本的恢复风险。

## status_part_see 与平台明确提示

用户提供作品 `7590781747764989413` 的实际 JSON：业务状态 0、详情明确 null、过滤作品 ID 匹配、原因 status_part_see，同时明确提示由于隐私设置无法查看。原来的原因码白名单没有覆盖它，导致暂无法确认。

在保留成功业务码、精确 ID、明确空详情、嵌套冲突与正向详情保护的前提下，使用已经核实的平台说明文字和 notice 组合判断当前不可观看，不再逐个枚举隐私原因码。登录、验证、限流、网络及稍后重试提示仍优先作为无法确认；不熟悉的提示文字也仍无法确认。原因码本身不等于失效，不根据码名猜测永久删除。

继续仅使用 JSON，无网页复核。原文件、读取记录和 NAS 数据不因核验不可访问而删除。以后恢复访问，由用户手动重试历史下载。

## 验证边界

新回归用例先在旧行为上失败，再修复并通过。独立审查发现的配乐删除入口遗漏已补齐，复审相关 24 项测试通过，没有剩余重要意见。

完整回归也发现原有 3 万条大库测试把 1000 个已保存的原作失效记录当作问题，按本次规则应为零。测试改为给这 1000 条记录设置真实封面显示问题，保留大库分页、排序和取消后保留未检查问题的覆盖，专项通过；这不是忽略产品失败。

复查上一版云端运行 [39606382990](https://github.com/wjh183322/CangXia/actions/runs/39606382990)，四个完整测试分片及服务端通过，桌面打包后的大小排序断言失败。审查发现断言只等待任意卡片出现便截取作品集合，并冻结可能随后因文件检查而变化的大小排序预期；现有日志不足以确认当时具体触发哪一种竞态，不能据此断言只是环境偶发。现在先等待全部本地作品进入 DOM，固定原始来源顺序，再按当前大小重算预期，并检查采样前后 libraryRevision 一致；成员顺序断言保留，失败时输出实际、预期和版本。不以排序后的 DOM 顺序作为后端输入，避免弱化同大小作品的顺序检查。

真实 Windows Chromium 文件句柄专项 11 项检查，分别验证未释放时的目录锁、所选作品释放后的即时移动、禁止重新获取句柄、其他作品仍可读、独立配乐删除以及同作品封面不受音频门禁影响。移动操作仅使用测试自己创建的临时文件，不等于在用户真实目录执行了删除验收。

完整套件、源码与打包后的专项、两个实际分发 EXE 的结果及校验值见[版本验收记录](../releases/backup-v0.3.42-verification.json)。云端验证单独报告，不把本机和合成账号测试表述为用户真实账号验收。

# 0.3.40 两个不可访问作品的 JSON 漏判

日期：2026-10-21。修复版本 0.3.41，NAS 不变，仍为 0.2.4。

## 实际证据与原因

用户提供了两个已登录浏览器中的真实详情 JSON：

| 作品 ID | filter_reason | 平台提示 | 0.3.40 的结果 |
| --- | --- | --- | --- |
| 7689008683628901478 | status_friend_see | 由于对方隐私设置，无法查看，去看看其他作品吧；作品暂时无法查看 | 暂无法确认 |
| 7684245301557820859 | status_deleted | 因作品权限或已被删除，无法观看，去看看其他作品吧；抱歉，作品不见了 | 暂无法确认 |

两者均为业务状态 0、详情明确 null、过滤对象 ID 与目标完全匹配。0.3.40 的消息判断已经支持这些文字，但原因码仅覆盖此前提供的 author_secret 和 status_self_see，因此没有返回不可访问结果。这是原因码覆盖不足，不是本地文件完整度判断错误。

独立匿名请求中，两条目标与正常视频对照均返回 HTTP 403，未取得有效详情。该结果只说明此次匿名请求未成功，不能用于判断某个作品失效。本次修复依据用户提供的实际 JSON，不依赖匿名浏览失败或界面截图推断。

截图中的“抖音网页尚未就绪”是另一个已记录的下载错误，来自接口请求前的账号浏览器环境准备，不能和本次原因码漏判混为一谈。本修复不改变登录浏览器或准备阶段，也不把该错误当作作品失效证据。

## 有界修复

保留已有成功业务码、完整 ID、访问警告、双层冲突与正向详情保护，只增加两份真实响应的原因码组合。status_friend_see 与已有隐私分支共用当前账号不可访问的说明；status_deleted 与已有权限或删除分支共用说明，并明确要求详情为 null。不单凭代码字面推断永久删除。

失效判定继续使普通下载任务退出失败列表并跳过补齐；已下载文件、读取记录和 NAS 元数据保留。文件状态和原作品状态不合并：文件完整的作品仍应显示无文件问题，同时显示原作品已失效。以后核验恢复为可访问，不自动重启历史失败任务。

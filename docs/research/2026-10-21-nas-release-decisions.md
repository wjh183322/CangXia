# 本次实施裁定与限制

以下整理本计划全部 Ruling，保留原因和代价，供后续审阅。

1. 管理型/Git worktree 均创建失败后，在现有检出使用独立 feature 分支；显式暂存、仅自有测试目录、不重置工作区。代价：隔离性较独立检出弱，需核对暂存范围。
2. 已完成恢复的重试先返回原回执，再处理过期版本；命令与内容摘要必须相同。代价：回执最小凭据长期占用少量空间，但不重复写入或删除。
3. 协议 3 缺少范围证明只代表原始 generation 0；显式正版本必须完全匹配，已删范围必须有恢复授权。代价：旧写入流程需配套升级，不自动绕过删除。
4. 普通同步不得用 null/hidden 或旧删除接口实现 NAS 移除；所有 NAS 删除产生版本与回执。代价：旧桌面不能写新服务，保留本机浏览。
5. 原有仅 NAS 删除入口仍保留独立选择，不悄悄扩大为删除本机；本机副本进入显式保留恢复流程。代价：界面多一个明确范围选择。
6. 整个作品目录的同意绑定稳定路径/归属/目录身份；同目录后来完成的素材属于已确认整目录，嵌套其他作品或共享配乐则拒绝。代价：整目录中的附带文件也会移入回收站，确认框提示该范围。
7. 全量回归并发固定为 2，替代计划原先 4；本机并发 4 曾触发原生 Node 崩溃。代价：验证较慢，不降低断言或跳过测试。
8. 宿主截图出现 UnknownVizError 时记录捕获失败，保留功能、真实解码和几何断言；不冒用旧截图。代价：部分宿主截图证据可能缺失，布局检查仍实际运行。
9. 独立审查不覆盖真实遵义/重庆、真实 NAS 与用户回收站；不据此认定实机验收。Linux 镜像与 Windows 分发载荷由单独发布门槛验证。代价：仍需用户安装后确认实际环境。

审查：无 Critical、三项 Important 均已修复，无延期 Minor。未修改或清理用户真实资料、真实 NAS、其他计划目录和私有清理盘点。

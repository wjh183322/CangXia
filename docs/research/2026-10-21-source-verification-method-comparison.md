# 作品状态：接口 JSON 与网页复核的对照研究

## 结论

后续已读取官方网页的详情转换、视频和图文路由代码，并实测图文详情接口；新增证据与修正建议见[进一步核实](2026-10-21-empty-detail-and-note-route-verification.md)。官方当前会将调用成功但没有详情转换为内部 404，可以据此设计严格的空过滤响应判定；单独 null 或接口状态 0 仍不足以判定。用户最终选择仅使用 JSON，0.3.40 已按该方向删除网页复核，见[实施记录](2026-10-21-json-only-source-verification.md)。以下保留初次调查经过及 0.3.39 的实际实现范围，其中混合判定建议已被最终选择替代。

## 用户样本

可播放的 `1.txt`：在内存中忽略开头多出的一个左花括号后解析成功，原文件未修改。顶层只有 `aweme_detail`、`log_pb` 和 `status_code`；作品 ID 为 `7689084254681498725`，类型为视频。它包含详情对象、多组播放地址，`status.is_delete` 为 false、`private_status` 为 0。现有解析器能够确认对应详情包含媒体资源。文件含不必要的鉴权字段，本研究不复制响应正文、鉴权值或签名媒体地址到仓库。

不可用样本 `7682371267983207909`：调用成功，`aweme_detail` 为 null；`filter_detail.aweme_id` 与目标一致，`filter_reason` 为空，没有原因文字。它确认本次接口没有提供该作品资源；“作品不存在”另有网页证据。

两条样本的 `status_code` 都是 0。因此不能用 0 判定作品失效。完整详情和媒体资源可以支持正向判断；“详情为空”的反向判断还需排除登录、限流、请求异常和不同类型的数据路径。当前尚未获得证明“空原因过滤响应在全部这些条件下只能对应失效”的对照证据，不推断未知枚举的含义。

## 视频网页的实际漏洞与速度

只读、未登录的隔离 Chrome 访问了用户给定视频，实际观测到：错误文字位于 `P[data-e2e="error-page"]`，下一步操作也是具有 pointer 光标的 P 元素。0.3.38 只以 a/button/role=button 为下一步操作证据，漏掉了这个真实结构，因而不断等到超时。

候选修复直接识别可见的官方错误区，同时保留作品 URL、账号会话、评论/推荐排除、登录/验证/限流保护和未完成详情请求保护。不会把任意页面文字当成失效。

原实现还对每个页面禁用了全部 HTTP 缓存，导致重复加载静态脚本。临时对照探针采用真实错误区识别并允许缓存后，这条公共视频一次约 5,864 ms 确认为不存在；下一次约 1,918 ms 遇到登录提示，正确保留未知。其他冷启动试验也出现过页面未加载完成的超时。这些是匿名公共页面的单次观测，不能视为遵义电脑已登录账号的性能承诺。

候选正式实现允许静态资源复用；遇到对应作品文档或详情的内存、磁盘、预取、service worker 缓存证据时，先关闭旧的自有临时页，再禁用缓存实时复核一次，沿用原来的总超时，不叠加第二个 10 秒。重复缓存仍保留未知。图片和媒体传输仍阻止。

截图中的 38 条未知如果每条额外等待 10 秒，会累加接近 380 秒。修复错误区识别可避免已出现有效证据时仍耗满预算；正常的网页网络加载仍有额外成本，不承诺等同于只调用接口的耗时。

## 图文 note 的初次观察与后续补证

只读访问了 `https://www.douyin.com/note/7698014329241074098`。本次匿名访问未观察到 `aweme/detail` 请求；主文档响应中存在约 20 万字符的 `RENDER_DATA`，顶层为 app，包含路径、环境和配置等数据。

“HTML 中出现作品 ID”不等于“含有可播放的完整作品对象”。本次没有从这些数据中取得匹配 ID 的完整图片详情，并遇到了登录提示。因此尚未确认该正常登录图文的数据究竟位于主文档的其它初始状态、其它 JSON 请求，还是已有页面状态中。

未看到 `aweme/detail` 请求不能用于判定图文失效，也不能证明这个接口不能按 ID 单独查询。图文正向证据应检查匹配作品的图片资源；不能用有没有视频播放地址作为图文有效性的标准。

初次曾请求正常显示图片时的主 Document 响应正文。后续补证已通过同一详情接口取得该图文的匹配详情、类型 68 及 1 张图片，且官方图文路由确实调用相同接口；当前研究不再以取得 Document 为首选前提。初始数据的具体序列化位置仍未确认，也未加入正式判断。

## 方法比较

| 维度 | 接口 JSON | 渲染后的网页 |
| --- | --- | --- |
| 速度和资源 | 通常较快，无需加载整个页面 | 需加载 HTML 和脚本；缓存可减少重复开销 |
| 正常作品 | 匹配 ID 的详情及视频/图片资源提供直接证据 | 可以辅助核对，但不能混入推荐作品 |
| 失效作品 | 明确权限、审核或删除提示可以判定；后续官方源码支持对严格空过滤组合设计当前不可访问规则，正式代码尚未加入 | 对应页面的明确官方错误区可补足其他证据不足的接口 |
| 登录、限流、异常 | 保留未知，不能当成删除 | 同样保留未知，并停止相应的受限访问 |
| 图文 | 使用图文详情和图片资源，不能只看 video 字段 | 缺少详情 XHR 时需查证初始数据或实际接口，不能凭请求缺席推断 |
| 维护 | 需匹配返回结构及平台原因语义 | 还受 DOM、页面加载和 UI 变化影响，本次已实际出现 P 标签漏判 |

推荐以接口为主、网页为补充，并区分当前不可访问与永久删除。后续已确认图文支持同一详情接口，无需优先开发尚未确认的初始 HTML 数据解析。空过滤组合的新规则有官方源码和真实负例支持，具体条件及未完成的端到端边界见补充研究。

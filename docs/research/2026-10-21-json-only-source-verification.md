# 仅使用 JSON 核验作品状态

日期：2026-10-21。客户端版本 0.3.40；NAS 继续使用 0.2.4。用户确认目标是判断作品当前是否可访问，不区分永久删除、作者私密与暂时权限限制，并明确要求删除网页复核。

## 实现

- `shared/source-state.mjs` 新增已核实的空过滤组合：请求及业务成功，详情明确为 null，过滤对象 ID 与目标字符串完全一致，原因和具体提示为空。允许空状态文字及明确的 OK、success、成功、请求成功；其他未识别状态提示保留未知。
- 聚合检查所有顶层与嵌套状态提示，避免第一个“success”掩盖后面的登录或验证提示。拒绝业务失败、双过滤对象及矛盾包装结构，避免从冲突响应挑选一个信号判失效。
- `Collector.resolveWork` 仅使用接口 JSON，单条核验、批量核验及下载刷新资源共用该路径。等待请求返回后先核对取消信号，再更新记录。
- 删除 `Collector.verifyEmptySource`、`SystemBrowser.verifyWorkPage`、DOM 状态解析器及临时网页探针；不再为每条核验导航到作品网页、等待错误区、重试网页缓存或下载页面资源。
- 视频与图文均可使用匹配详情及媒体资源确认可访问。已验证的隐私、审核、权限等 JSON 响应继续支持。超时、登录过期、限流、错 ID、无法解析及证据不足保持暂无法确认。
- 已失效作品退出普通失败下载列表并跳过自动补齐；读取记录、本机文件及 NAS 备份保留。之后显式核验取得正常详情可恢复可访问状态，不自动重启历史失败任务。
- 普通接口请求保留既有账号绑定、请求前后会话核对、取消和限流保护；专用登录浏览器、手动打开原作品及公开链接导入保持原有用途。历史状态证据不迁移或清空。

## 验证范围

状态专项覆盖空原因负例、正常视频、正常图文、后续恢复、未知和警告响应、内外层冲突、停止请求、文件及 NAS 元数据保留、失败队列退休与恢复、下载中识别后继续其他任务。

真实隔离 Chrome 测试使用新建专用配置和合成响应，运行实际账号绑定与接口请求链路。检查一次空元组只调用一次详情接口、没有新增作品浏览目标或作品文档、没有请求图片和视频、停止及账号会话变化不写入失效状态。源码与打包实现运行相同检查；它不是用户真实抖音账号验收。

移除的旧测试针对已删除的网页探针、DOM 识别、页面缓存和隐藏网页生命周期；仍适用的隐私、队列、账号及取消保护迁入 JSON 测试。完整套件仍自动枚举全部 `tests/*.test.mjs`，CI 专项改为 JSON 测试及打包后的实际浏览器链路，没有留下指向已删除脚本的调用。

独立审查首先发现混合提示与双层业务码两个误判边界；新增测试复现后完成修正，最终复核未发现仍需处理的重要问题。额外定向检查还验证了请求取消后仍返回空成功 JSON 不会写入失效状态。

最终测试数量、分发文件 SHA256 及实际 EXE 解包启动结果记入[本机验收数据](../releases/backup-v0.3.40-verification.json)。本轮不将本机结果称为云端 CI 结果，不重新发布同版本 NAS 镜像。

本机最终结果：完整套件 646 项通过、零失败、零跳过；状态专项 61 项；源码和打包后的 JSON 浏览器测试各 21 项；原有后台账号读取测试 16 项；打包桌面集成 76 项。归档逐文件比对 93 个运行时文件，确认两个已删除的网页模块没有残留。两种实际 EXE 均独立解包，核对相同 ASAR 后使用隔离空资料目录启动成功，未注册安装到用户环境。

后续云端复核 `39602169897` 已验证源码 `7bbc6cb6c87ce267ea2b3568362bceb93a5baa6a`：四组分别 170、150、89、237 项，共 646 项通过，零失败、零跳过；desktop 与 server 均成功。验收数据已补充真实云端结果；它不代表后来新增的原因码已经在 0.3.40 中得到覆盖。

另保留一次验收失败记录：分发文件解包检查曾返回 7za 状态 2，原探针的断言没有打印底层输出，无法据此确定当时的具体原因。补充底层输出及清除旧结果的保护后，完整重跑两种实际 EXE 的解包、ASAR 一致性和启动检查均通过。没有把原失败直接归为环境偶发，也不把重跑通过表述为已修复某个安装器底层错误；最终校验值对应重跑验证的文件。

## 登录与读取

`config.py` 使用系统 Chrome/Edge 专用窗口登录，随后读取抖音会话；包含临时 profile 数据库读取、CDP 等路径。藏匣 v0.1.2 参考系统浏览器与 CDP 的做法，但只使用应用专用 profile，通信限制在本机回环地址，不扫描常用浏览器 profile 或其他调试端口。

也可以在藏匣里选择参考工具已经生成的 `config.json`，仅在本机导入会话及浏览器信息。登录信息用 Windows 加密存储，不上传到 GitHub，也不返回到页面脚本。

参考工具直接请求收藏夹接口，`fetch_collections()` 固定循环17次，每次把 cursor 加30。藏匣使用服务实际返回的游标及结束标记，保留分页完整性提示；读取只更新列表，下载仍由用户勾选触发。

## 图片是否为高清原图

`main.py` 的 `_parse_aweme_list()`：

- 图文作品取 `images[*].url_list[0]`。
- 视频单图取 `video.cover.url_list[1]`，只有一条时取第0条。
- 没有比较图片真实宽高，也没有确认作者上传原文件。
- 下载时直接保存响应字节，不做图片放大或重压缩；但统一写为 `.jpg`，实际文件格式取决于响应。
- 图片验证只检查文件是否大于10 KB，这不能证明是高清原图。

用此前的公开视频示例，在正常浏览器取得的**网页详情数据**上比较实际下载结果：

| 字段 / 选法 | 实际像素 | 字节数 |
| --- | --- | --- |
| origin_cover | 360×640 | 33,333 |
| cover_original_scale | 360×640 | 33,218 |
| cover 第二条地址（参考项目选法） | 440×330 | 20,839 |

该示例没有取得高清原文件。收藏列表接口可能给其他作品返回不同地址，因此本次结果不能推广为参考工具所有下载文件的尺寸结论。

藏匣 v0.1.2 比较实际下载的静态候选图片，选择像素面积最大的一张，保留源字段、尺寸、字节数和 SHA-256 比较记录。文件按真实响应格式保存，不放大、不重压缩，也不把视频截图冒充原图。不同候选可能是不同画面或裁剪，详情会显示选中的来源。

## 视频

参考项目按一组固定字段优先级收集播放地址，最后还会使用 download_addr；并未遍历 bit_rate 以比较所有实际分辨率。藏匣同时检查可用的分辨率字段和 bit_rate 信息，按可用像素及码率排序，不使用可能附加平台水印的 download_addr 兜底。

仍需用户用实际账号确认登录、全部收藏分页和收藏夹顺序；没有声称用模拟测试证明真实账号已成功同步。

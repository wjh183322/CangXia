# 藏匣读取诊断 0.1.0

用于“藏匣专用浏览器能读取收藏，软件收到 HTTP 403”的小范围对比。基于本地版 0.2.3 的直接请求参数，独立运行，不升级或改写正式版。

## 在出现问题的电脑上使用

1. 运行 `CangXia-Request-Probe-0.1.0-Windows-x64.exe`。
2. 选择平时测试所用的 Chrome 或 Edge，点击“打开专用浏览器”。诊断工具使用自己的浏览器资料，需要重新登录一次。
3. 在这个窗口完成扫码及抖音要求的验证，打开“我的 → 收藏”，确认作品能继续加载。
4. 返回诊断工具，勾选“我已在刚打开的专用浏览器里确认收藏能正常加载”，点击“开始对比”。测试期间保持浏览器停留在收藏页面，不要操作网页。
5. 完成后点击“保存诊断报告”，将 JSON 文件发回分析。不要提供 Cookie、验证码或浏览器目录。

每条路径最多请求一页，每页 10 条；两次测试至少间隔一分钟。出现访问频繁立即停止，不切换方式重试。网页本身加载收藏时可能按抖音自己的逻辑发送请求，这不属于工具的两次主动探测。

## 两条路径

- 当前软件方式：从上述浏览器读取当前会话，在临时 Electron 会话中调用 `session.fetch`，保持浏览器 User-Agent 和原版请求参数。
- 浏览器页面方式：在同一个已经打开的抖音页面里调用 `fetch`，允许网页原有的请求处理逻辑执行。不是重新实现签名算法。

报告仅含状态码、业务数字代码、数量、耗时、浏览器版本、是否存在已知签名字段等，不含 Cookie、签名值、账号 ID、作品 ID、作品内容或接口原文。签名字段存在不代表有效，浏览器请求成功也不能单独证明原失败由签名造成。

独立资料目录为 `%APPDATA%\藏匣读取诊断`，其中专用浏览器会保留自己的登录会话；报告只在主动保存时写出。工具不访问 `%APPDATA%\藏匣`、NAS 版或备份版目录，不读写媒体库、NAS 或媒体文件。正式版的扫码窗口不会改变。

## 构建与验证

在本地版仓库根目录执行：

```powershell
node --test tests/request-probe.test.mjs
node scripts/request-probe-desktop-test.mjs
npx electron-builder --config diagnostics/request-probe/builder.json --win portable --x64
```

已自动测试的环境使用合成数据，不代表在发生问题的另一台电脑已修复 403。需用该机导出的报告判断是否合入请求方式改动。
